## What a result tells you

<div class="gale-three">
<CardGrid>
	<Card title="A failed solve is a value">
		Solves, factorizations, and spectral methods return `Either[LinAlgError, A]` wherever
		singularity, rank deficiency, or an indefinite matrix is an ordinary outcome. Each failure has
		its own case, so a caller can match on a singular matrix and a mismatched right-hand side
		separately.
	</Card>
	<Card title="An iterative result says whether it converged">
		An iterative solver that exhausts its iteration budget still returns its last iterate, with
		the residual, the iteration count, and `converged = false`. A partial eigensolver may return
		only the pairs that met the tolerance. Returning is not the same as converging.
	</Card>
	<Card title="Shapes are checked at the call">
		Every vector and matrix records its dimensions. A product, sum, or solve whose shapes do not
		agree fails at that call with a `LinAlgError`, rather than with an index error somewhere
		deeper in the computation.
	</Card>
</CardGrid>
</div>

## Matrices you never store

An iterative method needs only the action of a matrix on a vector. `LinearOperator.fromFunction`
turns a procedure that computes *A x* into an operator that CG, GMRES, BiCGSTAB, and the other
Krylov methods accept.

## One portable core

With only `gale-core` on the classpath, Gale runs its own portable implementation, on the JVM
and under Scala.js. The published core needs no native library and no JVM flags.

On the JVM, an application can import an optional backend: the Vector API, or BLAS and LAPACK
through the foreign function interface. The backend then takes the calls it is eligible for, by
shape and layout, and leaves the rest to the portable code. Result types, ownership, and
documented numerical meaning do not change. Bit patterns may: a backend can reassociate
floating-point arithmetic, so Gale promises shapes, orderings, failure modes, and numerical
invariants rather than identical bits. [The numerical contract](advanced/numerical-contract/)
states exactly what is guaranteed.

## Status

<Aside type="note" title="First milestone">
	`0.1.0-M1` is on Maven Central for the JVM and Scala.js. It is a milestone, not a 1.0
	compatibility freeze. The Breeze interop module and the JVM backends are tested but
	provisional, and are not part of the published bundle. A page marked as a development preview
	describes an API that is not yet in a release.
</Aside>

Gale is built with Scala 3.7.4 and needs JDK 21 on the JVM. Add the core to `build.sbt`:

```scala
scalaVersion := "3.7.4"
libraryDependencies += "io.github.canardlapin" %% "gale-core" % "0.1.0-M1"
```

For Scala.js or a cross-project, use `%%%` in place of `%%`, with the Scala.js plugin enabled.
[Modules and platforms](reference/modules-and-platforms/) lists every module and the runtime it
needs.
