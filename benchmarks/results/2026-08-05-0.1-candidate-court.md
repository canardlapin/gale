# Gale 0.1 bounded candidate court

Date: 2026-08-05

Measured source: `1b59fedcf1463142abfa149c2befa63a2bc63848` on
`release/0.1-stabilization`. The tracked tree was clean when the measurements
started; the JSON and CSV files named below are the generated evidence.

Machine: MacBook Pro, Apple M3 Max (14 cores, 36 GB), macOS 14.3 arm64.

Runtime: OpenJDK 22 (`22+36-2370`), sbt 1.11.7, Scala 3.7.4, JMH 1.37, pure
Gale backend.

## Evidence boundary

This is a bounded pre-M1 court. It checks that representative kernels and
downstream-shaped workloads execute, that reusable destinations and plans still
remove the allocations they are designed to remove, and that spectral timings
are paired with exact convergence and work accounting.

The court used one thread and one fork. Dense kernels, GEMM, pivoted QR,
multi-RHS QR, and CG used two 250 ms warmups and three 250 ms measurements.
The allocation and spectral groups used one 200 ms warmup and two 200 ms
measurements. Every run used the JMH GC profiler. These short runs do not have
enough samples to establish a universal speed claim, a new routing threshold,
or a statistically precise regression bound. Existing release-grade crossover
receipts remain authoritative for automatic backend policy.

## Spectral convergence and work

The convergence-equivalent clustered fixture completed all four requested
pairs for every engine. Its exact work counters and bounded timings were:

| Engine | Exact work | Time | Allocation |
| --- | --- | ---: | ---: |
| LOBPCG, identity | `4/4 @ 14; A=112, B=60, P=56` | 17.655 ms/op | 14,792,690.601 B/op |
| LOBPCG, preconditioned | `4/4 @ 7; A=56, B=32, P=28` | 8.479 ms/op | 7,300,725.433 B/op |
| Lanczos, exact metric solve | `4/4 @ 3; A=112, B=112; solves=48` | 10.490 ms/op | 7,944,239.278 B/op |
| Lanczos, iterative metric solve | `4/4 @ 3; A=112, B=208; solves/inner/applications=48/48/96` | 11.302 ms/op | 9,132,295.148 B/op |

Here `P` is the outer-preconditioner application count. The results preserve the
existing explicit-engine policy: problem-aware LOBPCG did the least work on
this fixture, while exact and iterative Lanczos remain named alternatives.
The short run does not justify automatic routing.

The stiffness/mass control is intentionally difficult. At `n=512, k=4`, all
four engines completed `0/4` requested pairs within their iteration budgets.
Its 48.813, 51.192, 69.704, and 100.159 ms/op results therefore measure four
different exhausted work paths and must not be ranked as solver speed. In
particular, iterative Lanczos performed 5,453 inner iterations and 5,773 inner
operator applications. The complete 72-cell work matrix is retained in
[the CSV receipt](./2026-08-05-0.1-candidate-spectral-work.csv).
